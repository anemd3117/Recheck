# 분석 범위 선택과 도구 준비

프로그램 비교 화면에서 **정적분석**, **동적분석**, **둘 다 분석** 중 하나를 고릅니다. 기본 선택은 **둘 다 분석**입니다. AI의 결과 설명과 추가 확인은 분석 범위와 별도로 선택합니다.

| 선택 | 수집하는 근거 | 실행 입력 | 결과 해석 |
| --- | --- | --- | --- |
| 정적분석 | 함수, 호출 관계, 추정 의사 코드 등 파일에서 읽은 구조 | 사용하지 않음 | 구조의 유사점과 차이. 실행 동작은 검증하지 않음 |
| 동적분석 | 같은 입력에 대한 표준출력·표준오류·종료 코드 | 두 프로그램에 동일하게 적용 | 유효하게 실행·관찰한 입력 범위의 일치 또는 불일치 |
| 둘 다 분석 | 정적 근거와 동적 관찰을 각각 수집 | 두 프로그램에 동일하게 적용 | 구조와 실행 결과를 구분하여 확인 |

정적분석만 선택하면 실행 입력을 사용하지 않습니다. 동적분석만 선택하면 Ghidra로 파일을 디컴파일하지 않습니다. 정적분석의 함수 구조 유사도는 동작 일치율이 아닙니다. 동적분석에서 등록한 입력이 모두 일치해도 모든 입력에서의 동등성을 증명하지 않습니다.

## 도구가 없을 때

선택한 범위에 맞는 도구 준비 상태와 설치 안내를 확인합니다. 분석을 시작하기 전에 필요한 도구를 점검하고, 준비되지 않았다면 표시된 안내를 따라 **도구 설치·관리**에서 설치하거나 분석 환경을 준비합니다. 다른 분석 범위로 자동 변경하지 않으므로 범위를 바꾸려면 직접 다시 선택하세요.

| 분석 경로 | 필요한 도구 | 준비 방법 |
| --- | --- | --- |
| 내장 환경으로 정적분석 | Docker Desktop, Recheck의 구조 분석 이미지 | Docker를 실행한 뒤 **분석 도구 내려받아 준비** |
| 직접 설치한 Ghidra로 정적분석 | Ghidra와 호환되는 Java JDK | 공식 설치 안내를 따라 설치한 뒤 도구 자동 찾기·고급 설정에서 경로 확인 |
| 동적분석 | Linux 컨테이너를 사용하는 Docker Desktop, Recheck의 실행 이미지 | Docker를 실행한 뒤 **분석 도구 내려받아 준비** |

자동 정적 경로는 사용 가능한 내장 분석 환경을 우선 사용하고, 가능한 경우 직접 설치한 Ghidra를 사용합니다. 직접 설치한 Ghidra는 모든 형식을 대체하지 않습니다. 예를 들어 .NET 메타데이터 분석에는 해당 기능이 있는 내장 분석 경로가 필요합니다. 명시적으로 고른 분석 경로가 실패하면 다른 경로로 몰래 바꾸지 않습니다.

도구 설치와 분석 환경 다운로드는 사용자가 해당 동작을 선택했을 때만 진행합니다. 단순 상태 확인으로 설치를 시작하거나 Windows 가상화 설정을 바꾸지 않습니다. 설치 관리자의 권한 승인·이용 조건 확인·재시작 안내가 나오면 본인이 확인해야 합니다. WinGet을 사용할 수 없으면 도구 설치 화면의 공식 다운로드 안내를 이용하세요. 기존 모델·인증 정보·분석 기록은 분석 범위를 바꿔도 유지됩니다.

Docker 설치, Docker 엔진 실행, Recheck 분석 이미지 준비는 서로 다른 상태입니다. Docker가 설치되어 있어도 엔진이 꺼져 있거나 분석 이미지가 없으면 추가 준비가 필요합니다. 자세한 순서는 [처음 실행 안내](FIRST_RUN.md)와 [컨테이너 분석 환경](CONTAINER_RUNTIME.md)을 참고하세요.

## 지원하지 않는 파일과 설치 문제 구분

현재 동적분석은 **Linux x86-64 ELF 콘솔 프로그램**을 지원합니다. Windows PE·DLL·.NET·Mach-O 파일의 정적분석 가능 여부와 해당 파일을 실행할 수 있는지는 별개입니다. 이 파일들에 Docker를 추가 설치하는 것만으로 Windows·macOS 실행 검증이 활성화되지는 않습니다. 현재 지원하지 않는 동적분석은 그렇게 안내하며, 대상 파일을 Windows 호스트에서 대신 실행하지 않습니다.

ZIP·패키지 구성 비교는 별도의 작업 모드입니다. 파일의 추가·삭제·변경을 확인하며 이 세 분석 범위나 실행 동작의 동등성 판정과는 다릅니다. [패키지 비교 안내](PACKAGE_COMPARISON.md)를 참고하세요.

## AI는 별도 선택

AI 설명을 끄면 선택한 정적·동적 근거만 수집합니다. AI 연결이나 Ollama 설치는 AI를 사용하지 않는 분석의 필수 조건이 아닙니다. AI 설명을 켜면 준비된 연결·모델 하나를 선택하고 해당 연결의 전송 동의와 예산을 적용합니다. 실행 중에는 이번 선택을 고정하며 여러 AI를 자동 호출하지 않습니다. AI의 추가 확인도 선택한 정적·동적 범위를 넘는 작업을 실행할 수 없습니다.

Gemini 무료 시작과 추천 GPT 연결을 제공합니다. 어느 경로든 인증 저장과 응답 검증을 마쳐야 사용할 수 있습니다. 기존 저장된 AI 연결은 보존합니다. [AI 연결 안내](AI_CONNECTIONS.md), [Gemini 연결 안내](GEMINI_FREE_SETUP.md)를 참고하세요.

## 결과와 보고서

분석 결과와 HTML 보고서는 **정적분석**, **동적분석**, **AI 설명·추가 확인**의 상태를 따로 표시합니다.

- **선택하지 않음**: 이번에 요청하지 않은 범위입니다.
- **진행할 수 없음**: 요청했지만 도구·환경·지원 범위 등의 조건으로 진행하지 못했습니다.
- **부분 완료·실패·취소**: 관찰된 근거와 누락된 범위를 함께 확인해야 합니다.
- **성공**: 해당 분석 절차가 완료됐다는 뜻입니다. 두 프로그램의 실행 결과가 같다는 뜻은 아닙니다.
- **미기록**: 이전 분석 기록에 해당 범위의 상태가 충분히 남아 있지 않습니다. 전체 상태가 성공이어도 이를 근거로 누락된 동적분석을 성공으로 추정하지 않습니다.

정적분석만 성공한 결과에서는 실행 동작이 검증됐다고 표시하지 않습니다. 입력별 일치·불일치는 실제 유효한 동적 관찰이 있을 때 확인합니다.

## 개발 CLI 호환성

새 CLI에서는 분석 범위와 AI를 따로 지정할 수 있습니다.

```powershell
python -m recheck analyze --original original.bin --reimplementation changed.bin --tests tests.json --analysis-mode both --ai-mode off
```

`--analysis-mode`는 `static`, `dynamic`, `both`이며, `--ai-mode`는 `off`, `explain`, `agent`입니다. 기존 `--mode automatic|agent|static|dynamic` 호출도 호환되며 새 옵션을 지정하지 않았을 때 기존 의미를 유지합니다. 정적분석에 실행 입력 파일이 필요한지는 CLI의 `--help`와 오류 안내를 따르세요. 결과에 저장된 재현 인자 배열에는 이번에 선택한 범위와 AI 옵션이 포함됩니다.
