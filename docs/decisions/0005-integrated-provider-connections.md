# ADR-0005 · AI 연결 화면과 선택 가능한 내장 표시를 제품에 통합한다

- 상태: 수락 · 0.1.6 구현·Windows 미리보기 공개 배포 완료
- 날짜: 2026-11-17
- 적용 범위: Recheck 0.1.6 UI·Windows x64 미리보기 배포
- 대체·구체화: [초기 로그인 실험](0001-embedded-login-experiment.md), [공통 제공자 제안](0004-provider-onboarding.md)

## 배경과 문제

사용자는 별도 Python 실험 창을 넘어 Recheck EXE에서 사용할 수 있는 수준의 내장 연결을 요청했고, 잘 동작하면 배포하도록 지시했다. 기존 OAuth 검증·DPAPI 저장·실제 응답 검사를 재사용하면서 브라우저 표시와 인증 성공을 분리해야 한다.

## 결정

공통 제공자 선택과 공식 사이트 창을 기존 AI 연결 화면에 통합한다. ChatGPT는 내장 표시 체크박스와 시스템 브라우저 방식을 제공하고, Gemini·OpenAI·Grok·DeepSeek·Claude는 공식 키 콘솔과 사용자의 키 직접 입력을 안내한다. 제공자 정책을 우회하지 않는다.

후속 사용자 결정에 따라 로그인·키 발급의 기본값은 외부 브라우저이며, 모든 제공자의 내장 선택은 기본 해제로 유지한다. 화면 순서와 Google 제한의 상세 근거는 [ADR-0006](0006-external-browser-default.md)에서 구체화한다.

처음 연결할 때는 **ChatGPT 로그인** 또는 **제공자 이름 + API 키 발급**으로 수행할 일을 표시한다. 연결된 제공자는 **연결 상태 확인**으로 바꾸고 저장·새 로그인·응답 요청 없이 상태만 읽는다. **응답 다시 확인**, **다시 로그인**, **연결 해제**는 별도 동작으로 제공하며 진행 중에는 **연결 중단**을 표시한다. 앱 안에서 열지 여부는 체크박스로 선택한다. 실행별 AI 선택과 다중 AI 병렬 비교를 보류한 이유는 [ADR-0007](0007-single-ai-per-analysis.md)에서 구체화한다.

공식 페이지 표시, 사용자 승인, 토큰·서명 검증, 실제 응답, 기본 AI 선택은 별도 상태다. 새 키를 입력하면 검증 전 별도 연결로 취급해 기존 키와 선택을 보존한다. 검사 결과가 프로필·모델·인증과 결합되고 보안 저장된 경우에만 기본 AI로 사용한다.

완료 화면을 자동으로 다른 페이지로 넘기지 않는다. 사용자가 **다음 단계**를 선택해 도구 준비를 이어간다. 재실행 시 실제 계정 상태와 결합된 검사 기록으로 완료 여부를 복원하며, 인증 참조 문자열만으로 성공을 판단하지 않는다.

내장 ChatGPT의 정확한 공식 origin·로그인 화면에서만 확인 가능한 Google 로그인 선택지를 숨긴다. 사용자 요청에 따른 표시 조정이며 지원되지 않는 인증을 구현하는 기능은 아니다. 계정 선택·동의 화면, 다른 로그인 수단과 외부 브라우저는 변경하지 않고 입력값·쿠키·계정 자료는 읽지 않는다.

## 검토한 대안

| 대안 | 결정과 이유 |
| --- | --- |
| 기존 검증 서비스와 네이티브 UI·WebEngine 표시를 통합 | 채택. 인증 검증·저장·응답 확인의 기존 경계를 유지하고 사용자는 앱에서 준비를 이어갈 수 있다. |
| 모든 제공자의 로그인을 항상 내장으로 강제 | 기각. 제공자 정책과 지원 계약이 다르다. Google 인증은 내장 진행을 제한하며 ChatGPT 공식 안내는 시스템 브라우저다. |
| 웹페이지 이동만으로 로그인·연결 완료 표시 | 기각. 페이지 표시와 인증·추론 성공은 다른 사건이다. |
| 로그인 화면이 실패하면 외부 브라우저 자동 실행 | 기각. 사용자가 **기본 브라우저에서 계속**을 선택할 수 있는 안내를 유지한다. |
| 로그인 버튼을 누를 때마다 새 연결 시작 | 기각. 저장된 연결은 읽기만 하는 상태 확인을 먼저 제공하고, 재인증은 명시적인 별도 동작으로 제공한다. |
| 연결 유지를 위해 웹 비밀번호·브라우저 쿠키 보관 | 기각. 기존 보호된 앱 인증 저장소를 재사용하고 웹 세션은 임시로 유지한다. |
| 동작하는 연결의 키를 먼저 교체하고 사후 검사 | 기각. 새 키 실패 시 기존 연결을 잃을 수 있어 검증 전 별도 프로필을 사용한다. |
| 브라우저 콘솔에서 키·쿠키를 자동 수집 | 기각. 사용자가 공식 서비스에서 발급한 키를 직접 보안 입력한다. |

## 경계와 영향

인증 URL은 전용 UI 신호로만 전달한다. 로그·진행 이벤트에는 전체 URL, 쿼리, 원시 예외, 토큰, 계정 식별정보를 넣지 않는다. 취소·완료·프로필 변경 후 도착한 신호는 적용하지 않는다. 브라우저 세션은 연결마다 임시로 생성하고 페이지·팝업·프로필을 순서대로 정리한다.

마지막 연결 결과는 고정된 제공자·단계·오류 코드와 저장 여부의 참/거짓만 로컬에 기록한다. 계정 이름·이메일·프로필 ID·URL·토큰·원시 예외는 포함하지 않는다. 이 진단 기록이 실패해도 인증 처리는 중단하지 않으며, 기록 자체를 인증 성공의 근거로 사용하지 않는다.

OpenAI의 코드 교환에서 `invalid_grant`가 발생하면 공식 절차에 따라 발급된 등록 ID를 해당 작업의 메모리에 유지하고 새 인증을 한 번만 진행한다. 새 state·nonce·PKCE·인증 코드를 사용하고 기존 코드를 재전송하지 않는다. 전체 제한 시간을 늘리거나 아직 검증하지 않은 계정을 저장하지 않는다. 같은 연결 작업 안에서 웹 창을 교체할 때는 작업 취소 신호를 보내지 않는다. 재시도 실패는 오류로 남긴다.

WebEngine은 선택 표시 기능이지만 배포본에는 실행에 필요한 런타임을 포함해야 한다. 기존 onedir ZIP과 출처·파일 inventory 검증을 유지하며 Chromium 고지·대응 소스를 포함한다. 배포 편의를 이유로 보안 검사나 공급자 제한을 끄지 않는다.

## 검증과 재검토

[구현 설계](../superpowers/specs/2026-11-17-embedded-provider-connections-design.md), [작업 계획](../superpowers/plans/2026-11-17-embedded-provider-connections.md), [진행 기록](2026-11-17-embedded-login-work-log.md)을 따른다. 실제 계정과 frozen EXE 결과를 확인하기 전에는 기능 지원·배포 성공으로 표시하지 않는다. 실제 계정 범위는 [인증 상태](../AI_AUTH_STATUS.md)에 분리한다.

2026-11-17에 [PR #8](https://github.com/leekmny/Recheck/pull/8)을 병합하고 [0.1.6 Windows 미리보기](https://github.com/leekmny/Recheck/releases/tag/v0.1.6)를 공개했다. 최종 소스는 Python 2,162개·Node 7개 검사 통과와 Python 1개 건너뜀을 확인했고, 새 EXE의 실제 실행·고정 입력 정답·기존 연결 상태 복원을 확인했다. 정상 앱 데이터의 ChatGPT 한 연결과 Gemini API 두 연결의 준비 상태를 보존했으며 ChatGPT 도구 호출은 준비되지 않은 상태로 유지했다. 이는 모든 제공자의 실제 키·내장 로그인·새 계정·깨끗한 PC 설치를 확인한 결과가 아니다. 정확한 커밋·CI·배포 해시와 남은 범위는 [최종 공개 기록](2026-11-17-embedded-login-work-log.md#공개-배포-확인--016)을 따른다.

제공자 정책·콘솔 주소·인증 계약이 바뀌거나 실제 호환 문제가 확인되면 해당 경로를 재검토한다. 지원되지 않는 제공자의 내장 로그인을 성공한 것으로 일반화하지 않는다.
