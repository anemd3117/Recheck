# ADR-NNNN · 결정의 핵심을 나타내는 제목

- 상태: 제안 / 수락 / 기각 / 보류 / 폐기 / ADR-NNNN으로 대체 중 선택
- 날짜: YYYY-MM-DD
- 적용 범위: 관련 기능·브랜치·기준 버전

## 배경과 문제

어떤 상황에서 무엇을 결정해야 하는지 적습니다. 확인한 코드·요구와 아직 확인하지 않은 가정을 구분합니다.

## 판단 기준

- 선택에 영향을 주는 사용자 요구와 기술적 제약
- 보존해야 할 동작·데이터와 검증 범위

## 결정

선택과 이유를 먼저 적습니다. 실험 승인·구현 계획·운영 적용의 범위를 명확히 씁니다.

## 검토한 대안

| 대안 | 판단과 이유 |
| --- | --- |
| 선택한 대안 | 선택 이유와 감수하는 제약 |
| 검토한 대안 | 채택하지 않았거나 보류한 이유 |

실제로 검토한 대안만 남깁니다. 필요하면 기각·보류 항목을 나누고 다시 검토할 조건을 덧붙입니다.

## 영향

얻는 효과, 추가 비용·제약, 기존 사용자·개발·배포에 미치는 영향을 적습니다.

## 검증 상태와 확인 방법

확인한 코드·문서와 실제 실행 결과를 구분합니다. 수행한 검증의 명령·환경·결과 또는 해당 작업 기록을 연결합니다. 실패·미실행·미측정 항목을 명시합니다.

## 재검토 조건

무엇이 달라지거나 어떤 근거가 확보되면 결정을 다시 검토할지 적습니다. 다른 ADR로 대체한다면 양쪽 기록을 연결합니다.

## 근거와 관련 기록

- 공식 문서의 해당 페이지와 확인 날짜
- 관련 코드·이슈·PR·작업 기록

이 템플릿은 [MADR](https://adr.github.io/madr/)을 참고한 프로젝트용 축약 형식입니다. 공개 문서에는 키·토큰·쿠키·계정 식별정보·개인 자료·개인 PC 경로를 포함하지 않습니다.
