# ADR-0001 · 앱 내부 로그인은 별도 브랜치의 실험으로 한정한다

- 상태: 초기 실험 기록 · 제품 통합 결정은 [ADR-0005](0005-integrated-provider-connections.md)로 대체
- 날짜: 2026-11-17
- 적용 범위: `experiment/qwebengine-login` 브랜치, 기준 소스 0.1.5

## 배경과 문제

사용자는 로그인 화면까지 앱 안에서 열리는 전체 흐름을 시험하도록 승인했다. 현재 앱의 OAuth는 시스템 브라우저를 열고 loopback callback을 받아 검증한다. 앱 안에서 로그인 화면을 렌더링하는 선택은 로그인 버튼의 시각적 개선보다 범위가 크며, 제공자 정책·렌더링 의존성·세션 취급·Windows 패키징에 영향을 준다.

Google은 개발자가 제어하는 임베디드 user-agent로 OAuth 인증 요청을 보내는 것을 명시적으로 금지한다. [Google OAuth 2.0 정책](https://developers.google.com/identity/protocols/oauth2/policies)

OpenAI의 OSS Sign in with ChatGPT 문서는 인증 요청을 **시스템 브라우저**에서 열도록 명시한다. 확인한 문서는 QWebEngine을 지원한다고 설명하지 않는다. 이 사실을 모든 OpenAI 서비스의 임베디드 브라우저 사용에 대한 보편적 금지 조항으로 확대하지 않는다. [OpenAI 등록·로그인 문서](https://developers.openai.com/siwc/token-sharing-open-source/sign-in)

## 판단 기준

- 사용자가 요청한 앱 내부 로그인 경험의 가능성을 구체적으로 확인한다.
- 제공자의 지원 계약과 실제 화면 표시·인증 성공을 구분한다.
- 기존 로그인·DPAPI 자료와 공개 배포 경로를 실험 때문에 변경하지 않는다.
- 렌더링 방식을 결정한 뒤 로그인 버튼·진행 상태·오류 안내를 일관되게 개선한다.

## 결정

QWebEngine을 사용하는 폐기 가능한 실험을 별도 브랜치에서 진행한다. 이는 **실험을 해 보자는 승인**이며, 성공 판정·운영 지원·기본 로그인 교체·배포 의존성 추가를 승인한 결정은 아니다. 차단이나 호환성 문제도 실험 결과로 기록한다. 제공자 차단을 우회하거나 Google 정책과 충돌하는 경로를 운영 기능으로 채택하지 않는다.

네이티브 로그인 버튼과 상태 안내를 개선하는 방향은 채택하되, 구체적인 구현은 렌더링 방식 결정 뒤로 미룬다. 실험 결과를 보기 전에 완성된 UI나 지원 기능으로 기록하지 않는다.

## 검토한 대안

| 대안 | 판단과 이유 |
| --- | --- |
| 시스템 브라우저와 기존 네이티브 UI 유지 | 현재 구현과 OpenAI 문서의 흐름에 맞는다. 운영 경로의 기준으로 유지한다. 앱 내부 화면 경험을 확인해 달라는 요청까지 해결하지는 못한다. |
| 네이티브 버튼·진행 상태만 먼저 개선 | 개선 목표로 채택했다. 렌더링 결정을 앞두고 화면을 다시 바꾸지 않도록 이번 실험에서는 구현을 보류한다. |
| QWebEngine에서 전체 로그인 시험 | 브랜치 실험에 한해 채택했다. 정책·세션·렌더러·의존성 문제를 확인해야 하며 성공을 전제하지 않는다. |
| QWebEngine을 즉시 기본 로그인으로 배포 | 채택하지 않았다. 제공자 지원과 패키징·기존 인증 회귀가 확인되지 않았고 운영 변경 승인이 없다. |

## 영향

실험 결과를 실제 제약과 함께 검토할 수 있다. 반면 Qt WebEngine 구성과 렌더링 검증이 추가로 필요하다. 현재 런타임 의존성은 `PySide6-Essentials`이며, 배포 spec은 WebEngine 모듈을 제외한다. 실험 가능 여부와 현재 배포본에 포함할 수 있는지는 별도 문제다. [의존성 정의](../../pyproject.toml), [배포 spec](../../Recheck.spec)

## 검증 상태와 확인 방법

2026-11-17 Windows 실험에서 ChatGPT 공식 로그인 화면과 그 안의 Google로 계속하기를 통한 Google 로그인 입력 화면을 표시했다. 개인정보 입력·승인·콜백·토큰 교환·추론은 실행하지 않았다. 대기 중 취소·화면 지우기·종료와 기존 OAuth 자동 검사 32개 통과를 확인했다. 구체적인 명령·범위·남은 일은 [실험 작업 기록](../../experiments/embedded_login/README.md)에 남긴다. 기존 버전의 실제 계정 확인 범위는 [AI 인증 상태](../AI_AUTH_STATUS.md)에서 별도로 확인한다.

후속 기록은 화면 로드, 로그인 진입, callback·토큰 검증, 취소·실패 처리, 실제 추론을 나누어 남긴다. 각 항목의 성공·실패·미실행을 구분하고 민감정보는 제외한다. 소스 시험과 frozen Windows 배포 시험도 구분한다.

## 재검토 조건

실험 결과가 확보되거나 제공자가 지원 방식을 변경·명확히 안내하면 렌더링 선택을 다시 검토한다. 운영 적용을 제안하려면 제공자별 정책 검토, 기존 계정·취소·실패 회귀, WebEngine 재배포 구성, 실제 Windows 실행 확인과 별도 운영 결정이 필요하다. 실패한 실험을 제거하더라도 이 판단 기록은 보존한다.
