# ADR-0002 · 사용자 인증 저장을 유지하고 개발용 .env 도입을 보류한다

- 상태: 현행 유지 수락, `.env` 도입 보류
- 날짜: 2026-11-17
- 적용 범위: 소스 개발 환경과 AI 인증 자료

## 배경과 문제

여러 PC에서 개발할 때 키와 토큰을 GitHub로 함께 옮기지 않고 각자 설정할 수 있어야 한다. 현재 API 자격증명은 `env:NAME` 형태로 환경 변수를 참조할 수 있으며, 앱이 저장하는 사용자 API 키·OAuth 토큰은 Windows 현재 사용자 DPAPI로 보호한다. `.env` 파일은 이미 Git에서 제외하지만 자동으로 읽는 코드는 없다. `python-dotenv`도 현재 프로젝트 의존성과 lock에 포함되어 있지 않다.

`python-dotenv`는 `.env`의 값을 환경 변수로 읽는 개발 편의 도구다. 파일을 만들기만 해서는 앱에 적용되지 않으며 명시적인 로딩이 필요하다. 이 방식은 비밀정보 암호화나 사용자 인증 저장소를 제공하지 않는다. [python-dotenv 공식 문서](https://bbc2.github.io/python-dotenv/)

## 판단 기준

- 각 팀원과 PC가 자신의 인증 자료를 관리한다.
- 기존 사용자의 API 키·토큰·저장된 연결을 보존한다.
- 환경 변수 참조와 사용자용 보안 저장을 혼동하지 않는다.
- 편의를 위한 새 의존성·설정 우선순위는 필요성이 확인된 뒤 도입한다.

## 결정

사용자 인증은 기존 DPAPI 저장소를 유지한다. 개발자는 필요한 경우 이미 지원되는 프로필의 `env:NAME` 참조와 프로세스 환경 변수를 사용한다. `.env`는 선택 가능한 개발 편의안으로 검토했으나 **이번 변경에서 패키지·파일·자동 로딩 코드를 추가하지 않는다**. 사용자 키와 OAuth 토큰을 `.env`로 이전하지 않는다.

## 검토한 대안

| 대안 | 판단과 이유 |
| --- | --- |
| 앱 DPAPI 저장소와 기존 환경 변수 참조 유지 | 채택했다. 현재 구현으로 사용자 인증과 개발 설정을 분리할 수 있고 저장 자료 이전이 필요 없다. |
| 개발 전용 `.env` 로딩 추가 | 보류했다. 편의는 있지만 로딩 위치·우선순위·배포본 동작·문서·의존성을 함께 정해야 한다. 현재 요청을 처리하는 데 필수는 아니다. |
| 사용자 인증을 평문 `.env`로 통합 | 채택하지 않았다. 현재 DPAPI 보호를 대체할 수 없고, 사용자별 인증 저장과 개발 설정의 역할도 다르다. |
| 팀 공용 키·토큰 또는 인증 저장소를 저장소에 포함 | 채택하지 않았다. 각 작업자의 인증을 분리한다는 개발 방식에 맞지 않는다. |

## 영향

새 PC에서는 자신의 개발 환경과 AI 연결을 다시 준비한다. 소스·고정 의존성·문서는 공유하지만 가상환경과 인증 저장소는 복사하지 않는다. 현재 `.env` 파일에 값을 적어도 앱이 자동으로 인식하지 않으므로 기여 안내에서 이를 명시한다. [다른 PC에서 이어서 개발하기](../GITHUB_WORKFLOW.md), [기여 안내](../../CONTRIBUTING.md)

## 검증 상태와 확인 방법

[자격증명 저장](../../ai_providers/credentials.py), [프로필 처리](../../ai_providers/profiles.py), [공급자 생성](../../ai_providers/factory.py), [프로젝트 의존성](../../pyproject.toml), [고정 의존성](../../requirements-lock.txt), [Git 제외 규칙](../../.gitignore)을 확인했다. 이 기록은 새 계정 로그인이나 PC 간 인증 이전을 시험했다는 뜻이 아니다.

향후 로딩을 구현한다면 실제 환경 변수와 파일 값의 우선순위, 파일 미존재 시 동작, frozen 배포본의 제외 범위, 민감정보가 로그·설정·릴리스에 포함되지 않는지 확인한다. DPAPI 보존 회귀도 별도로 확인한다.

## 재검토 조건

팀의 반복적인 환경 설정 부담이 확인되고 개발 전용 적용 범위·우선순위·비밀정보 없는 예제 형식에 합의하면 `.env` 도입을 다시 검토한다. 도입하더라도 사용자 인증 저장소 변경은 별도 결정으로 다룬다.
