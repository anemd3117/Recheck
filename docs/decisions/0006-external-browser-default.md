# ADR-0006 · 외부 브라우저를 기본으로 하고 내장 표시는 선택으로 유지한다

- 상태: 수락 · 0.1.6 기본값 구현·공개 배포 완료, 계정별 확인 범위 구분
- 날짜: 2026-11-17
- 적용 범위: Recheck 0.1.6의 AI 연결·로그인·API 키 발급 안내
- 구체화: [ADR-0005](0005-integrated-provider-connections.md)의 브라우저 선택 기본값. 인증 검증·보호 저장·실제 응답 확인의 경계는 유지한다.

## 결정

사용자가 외부 창을 기본으로 요청했으므로 **로그인·키 발급 화면을 앱 안에서 열기** 체크박스는 처음에 해제한다. ChatGPT 로그인, Gemini API 키 발급, 다른 제공자의 공식 키 콘솔은 기본 브라우저에서 연다. 일반 공식 안내 페이지도 외부 브라우저를 기본으로 한다.

내장 브라우저 선택은 모든 제공자에 남긴다. 사용자가 체크하면 해당 공식 페이지의 내장 표시를 시도할 수 있으며, Google·Gemini 키 발급 페이지도 선택 대상에서 제거하지 않는다. 이는 미래의 공식 지원이나 호환 개선을 검토하기 위한 선택권이다. 현재 Google 로그인을 내장에서 완료할 수 있다는 약속은 아니다. ChatGPT 내장 로그인도 사용자가 선택하는 미리보기 경로로 남긴다.

공통 제공자 화면과 기존 Gemini 키 발급 버튼은 같은 선택을 따른다. 연결 안내 순서는 **권장 ChatGPT → Gemini 무료(API) → AI 계정 연결**로 정리한다. 여기서 무료 안내는 해당 제공자의 프로젝트·모델·할당량 조건을 따른다는 뜻이며, 모든 사용자의 무료 사용 가능성을 보증하지 않는다.

Google 인증 이동 제한과 **기본 브라우저에서 계속** 동작은 유지한다. 내장 실패가 외부 창을 임의로 실행하게 하지 않고, 사용자가 외부에서 계속하도록 선택한다. User-Agent 위장, 인증서 오류 무시, 웹 보안·샌드박스 해제, 다른 브라우저의 쿠키 가져오기로 제한을 우회하지 않는다.

## 배경: Google 페이지 표시와 로그인을 분리해야 하는 이유

Google AI Studio의 키 콘솔 화면이 그려지는 것과 Google 계정 로그인이 완료되는 것은 다른 단계다. 콘솔의 초기 화면·정적 자료가 표시되더라도 계정 선택, 로그인, 동의, 프로젝트 권한 확인 또는 키 발급은 뒤따를 수 있다. 따라서 화면 표시만으로 Google 인증 지원이나 Gemini 연결 성공을 판정하지 않는다.

Google OAuth 정책의 [Use secure browsers](https://developers.google.com/identity/protocols/oauth2/policies#browsers)는 개발자가 제어하는 내장 사용자 에이전트로 Google OAuth 승인 요청을 보내지 못하도록 규정한다. 스크립트 삽입, 요청 경로 변경, 세션 쿠키 접근이 가능한 라이브러리 등이 대상이며, 사용자가 요청 주소와 연결 보안을 확인할 수 있어야 한다. 이는 단순히 Chromium으로 HTML을 표시할 수 있는지와 다른 지원 조건이다.

일반 Google 계정 로그인에도 제약이 있다. [지원되는 브라우저로 로그인](https://support.google.com/accounts/answer/7675428?co=GENIE.Platform%3DDesktop&hl=en) 도움말은 다른 앱에 내장된 브라우저 등에서 로그인을 차단할 수 있다고 안내하고, CEF 기반 Google 로그인 개발자에게 브라우저 기반 OAuth 등의 대안을 제시한다. 이 도움말의 CEF 안내를 Qt의 모든 동작에 그대로 대입하는 것은 피하되, 내장 브라우저 로그인 전반의 공식 지원 제한으로 판단한다.

Google의 [내장 웹뷰 제한 배경 설명](https://developers.googleblog.com/en/upcoming-security-changes-to-googles-oauth-20-authorization-endpoint-in-embedded-webviews/)은 호스트 앱의 통신·화면·쿠키 개입 가능성, 주소·보안 표시, 분리된 저장소에 따른 SSO와 다단계 로그인 문제를 설명한다. 문서에 나오는 `disallowed_useragent`는 Google이 이러한 제한에 사용할 수 있는 오류의 근거다. **이번 Recheck 점검에서 그 오류를 Google 서버로부터 받았다는 증거는 아니다.**

현재 [provider_browser.py](../../recheck/provider_browser.py)의 `_allow_navigation`은 `accounts.google.com`과 그 하위 호스트로의 이동을 Recheck에서 먼저 거절한다. 따라서 이번 내장 Google 진행 불가는 적어도 앱이 문서화된 제한을 적용한 결과와 함께 해석해야 한다. 앱의 정책 안내를 Google 서버의 독립적인 거절 화면이나 실제 응답 코드로 기록하지 않는다. 다른 Google 호스트 전체를 차단한다는 뜻도 아니다.

## 브라우저 세션과 재로그인 마찰

Recheck의 내장 창은 저장 이름 없는 `QWebEngineProfile`을 만들고 메모리 캐시와 `NoPersistentCookies`를 사용한다. Qt의 [off-the-record 설명](https://doc.qt.io/qtforpython-6/PySide6/QtWebEngineCore/QWebEngineProfile.html#PySide6.QtWebEngineCore.QWebEngineProfile.isOffTheRecord)에 따르면 쿠키·캐시 등 통상 영속화되는 자료를 메모리에 둔다. 코드와 이 프로필 격리를 함께 보면, 사용자가 이미 로그인한 Chrome의 쿠키를 가져오는 구조가 아니므로 내장 창에서는 별도 로그인이 필요할 수 있다. 외부 브라우저의 기존 로그인 상태도 계정·브라우저 설정에 따라 달라진다.

초기 ChatGPT 실험에는 코드 교환의 `invalid_grant`와 복구 중 브라우저 프로필 정리로 인한 로그인 상태 상실이라는 서로 다른 문제가 있었다. 첫 오류는 인증 코드 교환 실패이며, 뒤의 재로그인 마찰을 그 오류의 서버 원인으로 단정하지 않는다. [OpenAI OSS 로그인 안내의 코드 교환](https://developers.openai.com/siwc/token-sharing-open-source/sign-in#3-handle-the-callback-and-exchange-the-code)은 `invalid_grant` 발생 시 기존 코드를 버리고 해당 시도에서 발급된 등록 ID를 유지해 새 승인을 시작하도록 설명한다. 같은 연결 작업의 복구에서는 임시 메모리 프로필을 보존하도록 별도로 개선하되, 작업 종료 후 영속 웹 세션으로 바꾸지 않는다.

OpenAI의 [승인 시작 안내](https://developers.openai.com/siwc/token-sharing-open-source/sign-in#2-start-authorization)는 시스템 브라우저를 열도록 명시한다. 이 공식 경로와 사용자의 기본값 요청이 외부 브라우저 채택의 근거다. 내장 표시 기능의 존재만으로 OpenAI가 그 경로를 공식 지원한다고 해석하지 않는다.

## 확인된 사실·해석·미검증 범위

다음은 2026-11-17 시점의 기록이다. 사용자 보고, 저장소·앱 점검, 공식 문서와 그로부터의 해석을 구분한다. 자세한 실제 계정 범위는 [AI_AUTH_STATUS](../AI_AUTH_STATUS.md)를 따른다.

| 구분 | 근거와 확인 내용 | 판정의 한계 |
| --- | --- | --- |
| 확인된 사용자 요청 | 외부 창을 기본으로 하고 체크박스를 해제하되, Google을 포함한 내장 선택 자체는 유지해 달라고 요청했다. | 기본값 결정은 사용자의 제품 선택이다. 모든 제공자의 내장 실패를 실측해 내린 결론으로 포장하지 않는다. |
| 확인된 사용자 보고 | 내장 Google·AI Studio 진행이 실패했다고 보고했다. | 키 콘솔 표시 여부와 계정 로그인 성공을 분리한다. Google의 특정 서버 오류는 확인되지 않았다. |
| 확인된 구현 | `_allow_navigation`이 Google 계정 호스트를 먼저 차단하고 내장 프로필은 메모리 전용이다. | 앱 자체 차단은 Google 서버의 `disallowed_useragent` 응답 증거가 아니다. |
| 앞선 앱 점검 | ChatGPT 화면에 `invalid_grant`가 있었고, 당시 점검용 저장소에는 ChatGPT 인증 자료와 실제 응답 검사 기록이 없었다. | 웹 로그인과 앱의 저장·추론은 다르다. 이후 정상 앱 데이터에서 확인한 연결 상태와 시점을 구분한다. |
| 확인된 사용자 보고 | Free 계정에서 현재 워크스페이스·요금제 권한을 사용할 수 없다는 안내를 봤으며, 이후 외부 웹 로그인 자체는 성공했다고 보고했다. | 모든 Free 계정이 미지원이라는 결론도, Recheck의 권한·토큰 저장·추론이 성공했다는 결론도 내리지 않는다. |
| 구현·공식 문서로부터의 해석 | 임시 내장 프로필은 기존 Chrome 로그인 세션을 자동 공유하지 않아 재로그인 마찰이 생길 수 있다. | 개별 실패의 유일한 원인으로 단정하지 않는다. Google 정책 제한과도 별개다. |
| 후속 앱 점검 | 정상 앱 데이터에서 ChatGPT 인증·외부 앱 사용 권한·실제 기본 응답·JSON·보호된 검사 기록을 확인했다. 도구 호출 검사는 통과하지 않았고 당시 기본 AI는 ChatGPT가 아니었다. | 기본 설명 준비, 도구 사용 준비, 이번 분석의 AI 선택은 각각 다르다. 이 결과로 모든 계정·모델을 일반화하지 않는다. |
| 최종 실행본·배포 확인 | 새 Windows EXE에서 기존 ChatGPT·Gemini 연결 상태 복원, 연결 상태 버튼·연결 해제 버튼, 내장 표시 기본 해제와 비교 AI 선택란을 확인하고 0.1.6을 공개했다. | 저장된 연결의 복원·표시 확인이며 모든 제공자의 새 인증·실제 추론을 다시 수행했다는 뜻은 아니다. |
| 미검증 | Free 계정의 새 내장 경로, Google 내장 로그인, 모든 제공자의 실제 키·계정, 깨끗한 PC·VM 설치. | 이전 버전의 성공, 외부 웹 로그인 보고, 모의 검사를 해당 경로의 성공으로 대체하지 않는다. |

## 대안과 영향

| 대안 | 결정과 이유 |
| --- | --- |
| 외부 기본 + 모든 제공자의 내장 선택 유지 | 채택. 사용자 요청을 반영하고 공식 브라우저 경로를 먼저 제공하며 향후 검토 선택권을 남긴다. |
| 내장을 기본으로 하고 실패 후 외부로 안내 | 기각. 사용자가 원하지 않는 첫 로그인·정책 제한·반복 입력을 기본 경험으로 만든다. |
| Google·API 키 페이지의 내장 선택 제거 | 기각. 내장 선택을 남기라는 사용자의 최신 지시와 맞지 않는다. 현재 지원 한계는 안내와 이동 제한으로 구분한다. |
| 모든 내장 브라우저 기능 제거 | 기각. 선택적인 표시·호환 검토 목적은 남아 있다. |
| 외부 브라우저 로그인만으로 연결 완료 처리 | 기각. 콜백·토큰 검증·권한·보호 저장·실제 응답 확인이 필요하다. |
| User-Agent·인증서·샌드박스 설정 변경 또는 Chrome 쿠키 복사 | 기각. 공식 지원 근거가 되지 않으며 기존 보안·세션 격리 경계를 훼손한다. |

외부 기본값은 사용자가 익숙한 브라우저에서 주소·보안 정보와 사용 가능한 로그인 도구를 이용하게 한다. 대신 앱과 브라우저 사이 이동이 필요하며, 브라우저의 계정 선택·회사 정책·콜백 환경에 따른 실패는 여전히 가능하다. 내장 선택은 앱 안에서 진행할 수 있는 장점과 별도 세션·제공자 제한·유지보수 비용을 함께 가진다. 어느 표시 경로든 페이지 로드, 웹 로그인, 앱 인증 저장, 실제 응답 검사를 각각 기록한다.

ChatGPT에는 외부 앱 사용 권한이 필요하다. 무료 계정에서 권한 제한이 나오면 지원되는 플랜의 계정이나 다른 AI를 안내하되 업그레이드를 자동 진행하지 않는다. 콜백 페이지의 일반 안내는 사용자의 실제 요금제·권한을 조회한 결과가 아니다. 확인된 서버 오류 코드와 계정 권한 검사의 결과만 해당 단계의 근거로 사용한다.

## 팀의 재검토·완료 기준

0.1.6의 최종 소스·실행본 확인과 [공개 배포](https://github.com/leekmny/Recheck/releases/tag/v0.1.6)는 완료했다. 아래 기준은 후속 변경에서도 유지한다. 계정별 실제 응답 범위, 실행·CI·배포 해시와 남은 확인은 [작업 기록](2026-11-17-embedded-login-work-log.md#공개-배포-확인--016)에 남긴다.

1. 깨끗한 초기 상태에서 공통 체크박스가 해제되고 ChatGPT·공통 키 콘솔·기존 Gemini 키 버튼이 외부 기본값을 따르는지 확인한다. 체크했을 때 각 제공자의 내장 표시를 선택할 수 있는지도 확인한다.
2. Google 내장 선택 시 정책 안내와 명시적 외부 계속을 확인한다. AI Studio 표시만으로 로그인을 통과 처리하지 않으며, 앱 차단과 공급자 응답을 구분한다.
3. ChatGPT는 외부 웹 로그인 이후 콜백, 서명·state·nonce·PKCE, 요금제 사용 권한, 보호 저장, 모델에 결합된 실제 응답 proof를 순서대로 확인한다. Free와 유료 여부는 실제 확인 범위와 서버 결과로 기록한다.
4. `invalid_grant` 복구는 같은 작업에서 발급된 등록 ID·메모리 세션만 유지하고 새 승인 자료를 사용한다. 취소·완료·새 작업 이후에는 이전 상태가 재사용되지 않는지 확인한다.
5. 실제 계정과 새 frozen EXE 결과가 확보되면 [인증 상태](../AI_AUTH_STATUS.md)와 작업 기록을 갱신한다. 성공하지 않은 단계는 대기로 남긴다.
6. Google·OpenAI의 공식 정책이나 지원 경로가 바뀌면 근거를 다시 읽고 내장 경로를 재검토한다. 내장 기본값을 다시 채택하려면 공식 지원 근거와 실제 계정·배포본 재현 결과, 사용자의 기본값 결정이 필요하다.

GitHub에 남기는 실패 기록에는 제공자·단계·고정 오류 코드·저장 여부·검증 범위만 적는다. 실제 이름·이메일·계정 ID·전체 인증 URL·토큰·쿠키·로컬 전체 경로·원시 예외·민감한 화면 자료를 포함하지 않는다. 이 ADR의 공식 자료는 **2026-11-17에 확인**했으며, 문서 근거와 이번 실험의 관찰을 서로 대신하지 않는다.
