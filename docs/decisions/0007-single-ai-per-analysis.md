# ADR-0007 · 분석마다 준비된 AI 하나를 사용자가 선택한다

- 상태: 수락 · 0.1.6 구현·Windows 미리보기 공개 배포 완료
- 날짜: 2026-11-17
- 적용 범위: AI 연결 상태, 프로그램 비교의 AI 선택, 분석별 요청과 결과 보관
- 관련 결정: [연결 화면 통합](0005-integrated-provider-connections.md), [외부 브라우저 기본값](0006-external-browser-default.md)

## 배경과 문제

여러 AI 계정을 연결해 둘 수 있어도, 연결된 계정과 이번 분석에 사용할 계정은 다르다. 저장된 연결을 다시 누를 때 새 로그인이나 API 키 발급을 시작하면 상태 확인과 재연결을 혼동하기 쉽다. 반대로 연결된 모든 AI에 분석을 자동 요청하면 사용자가 예상하지 않은 요청량과 비용, 서로 다른 결과가 생긴다.

사용자는 연결된 제공자의 상태 확인·연결 해제와 프로그램 비교에서의 AI 선택을 요청했다. 현재 하나의 프로필·모델·요청 예산을 전제로 한 분석 계약을 유지하면서 사용자가 실행 전에 선택을 확인하도록 한다.

## 결정

연결된 제공자의 주 버튼은 **연결 상태 확인**으로 표시하고 통신 없이 저장된 상태만 읽는다. **응답 다시 확인**은 기존 검사 결과를 보여 주는 동작과 구분해 실제 요청을 보내며, 사용량·한도가 적용됨을 안내한다. 새 로그인과 키 발급도 별도 동작이다. 진행 중에는 **연결 중단**으로 작업을 취소하고, 연결된 상태에서는 **연결 해제**를 제공한다. 상세 설정의 중단 버튼은 **현재 연결 작업 중단**으로 표시한다.

AI 설명을 사용할 때 **프로그램 비교**에서 검증된 연결과 모델 하나를 고른다. 이번 비교의 선택은 저장된 기본 프로필과 역할별 연결 설정을 변경하지 않는다. 선택한 프로필·모델·전송 동의·요청 예산은 실행을 시작할 때 분석용 설정 사본에 고정한다. 실행 중 설정을 편집하더라도 이미 시작한 분석의 AI를 바꾸지 않는다. AI 설명을 끈 분석과 ZIP 구성 비교는 AI 선택 없이 사용할 수 있다.

연결된 모든 AI를 자동 호출하거나 실패 시 다른 제공자로 자동 전환하지 않는다. **다중 AI 병렬 비교는 이번 버전에 구현하지 않는다.** 같은 근거를 다른 AI로 분석하려면 사용자가 별도 실행에서 해당 AI를 선택한다.

## 검토한 대안

| 대안 | 결정과 이유 |
| --- | --- |
| 실행 전 AI 하나를 명시적으로 선택 | 채택. 사용자가 요청 대상과 예산을 확인할 수 있고 기존 분석·근거·결과 보관 계약을 유지한다. |
| 저장된 기본 AI만 사용하고 비교 화면에는 표시하지 않음 | 채택하지 않음. 여러 계정이 준비된 경우 이번 요청의 대상을 확인하기 어렵다. 기존 기본 선택은 초기 선택에 활용할 수 있다. |
| 연결된 AI에 모두 자동 요청 | 보류. 제공자마다 요금·할당량·기능이 다르며 요청 수가 늘어난다. 동의·예산·부분 실패·결과 보관을 먼저 설계해야 한다. |
| 한 AI가 실패하면 다른 AI로 자동 대체 | 채택하지 않음. 사용자가 고른 계정·전송 대상·예산을 바꾸며 실패 원인과 결과의 출처를 흐린다. |
| 분석 중 전역 설정을 계속 읽어 AI를 교체 | 채택하지 않음. 한 실행의 응답 출처와 요청 예산을 재현하기 어려워진다. |

## 영향과 검증

사용자는 여러 연결을 준비하되 매 분석의 대상을 하나로 확인한다. 기본 응답·JSON 준비와 도구 호출 준비는 서로 구분하며, 연결이 있다는 이유만으로 지원하지 않는 기능을 활성화하지 않는다. 실제 계정 점검 범위는 [인증 상태](../AI_AUTH_STATUS.md), 최종 소스·실행본 결과는 [작업 기록](2026-11-17-embedded-login-work-log.md)에 남긴다.

검증에서는 저장된 상태 확인의 무요청·무변경, 제공자별 연결 해제, 진행 중 취소, 준비되지 않은 연결의 선택 방지, 실행 시작 후 프로필·모델 고정, AI를 끈 분석과 ZIP 비교를 확인한다. 구현·자동 검사·실제 계정·배포본의 결과는 각각 기록한다.

0.1.6은 최종 전체 소스 검사와 독립 검토를 통과했고, 실제 Windows 실행본에서 기존 연결 상태·제공자별 버튼·기본 해제된 내장 선택·비교 AI 선택란을 확인한 뒤 [미리보기 릴리스](https://github.com/leekmny/Recheck/releases/tag/v0.1.6)로 공개했다. 기존 준비된 인증 세 개는 바꾸지 않았으며 ChatGPT 도구 호출 미준비도 그대로 표시했다. 한 번의 비교에 AI 하나를 고정하는 계약과 전역 기본값 보존은 자동 회귀로 확인했다. 모든 AI의 실제 추론이나 다중 병렬 비교를 검증한 것은 아니다. 상세 근거·해시·미검증 범위는 [공개 배포 기록](2026-11-17-embedded-login-work-log.md#공개-배포-확인--016)을 따른다.

## 병렬 비교를 다시 검토할 조건

사용자가 병렬 비교를 필요로 하고 다음 계약이 준비되면 별도 설계로 검토한다.

- 요청 전에 사용할 AI 각각과 전송 범위, 예상 요청 수를 확인하고 명시적으로 실행한다.
- 제공자별 예산·동시 실행 수·한도 오류를 관리하고, 한 제공자의 실패나 취소가 다른 결과를 지우지 않는다.
- 같은 고정 근거를 사용하되 응답·모델·시각·요청량·실패를 AI별로 보관한다.
- 전체 취소와 개별 취소, 재시도, 앱 종료 후 복구를 정의한다.
- 서로 다른 응답을 AI의 자기 채점만으로 합치거나 정확도 순위로 표시하지 않는다.

병렬 비교가 유용할 수 있다는 점과 이를 구현·검증했다는 주장은 구분한다.
