파일은 비공개 보관본에 남아 있으며 이 공개 저장소의 이력이나 공개 다운로드가

## 사용자 동선

로그인 → 계정 모델 조회/추천 선택 → 실제 응답/기능 확인 → 기본 AI 저장 → 설치된 도구 준비 → 파일·입력 선택 → 비교 → 실제 출력과 AI 설명 확인. 첫 화면에는 다음 단계 버튼을 두고, 다른 제공자·주소·인증 등록·예산은 고급 영역으로 접었다.

시작·비교·빈 결과·지난 분석·작업 기록·기본 AI 설정·고급 AI 설정·도구 설정·PC 성능·작은 비교 창의 10개 화면을 실제 Qt 앱에서 확인했다. 960×640 논리 크기에서도 비교 시작 버튼을 유지하고 입력 영역은 스크롤할 수 있다. 실제 비교 결과 화면도 별도 확인했다. 이는 사용자 연구나 접근성 인증을 대신하지 않는다.

## 재현한 문제와 수정

1. ChatGPT 계정 모델 목록이 OpenAI API 키 목록과 다른 형식이었다. `models/slug/visibility=list`를 읽고 서버 순서를 보존한다. 숨김 항목은 제외한다.
2. 정상 완료 응답의 `incomplete_details: null`을 객체로 가정해 실제 답변을 거부했다. null만 빈 세부 정보로 처리하고 잘못된 타입과 미완료 응답 검증은 유지한다.
3. 도구 자동 설정이 무관한 원격 AI proof까지 비워 재시작 후 기능 확인을 잃었다. 변경되지 않은 프로필의 보호된 proof 참조를 유지하고 실제 결합 검증은 매번 적용한다.
4. 로그인만 끝나고 모델·기능·기본 AI 선택을 사용자가 따로 해야 했다. 동일한 ChatGPTSetup 흐름으로 연결하고, 이미 유효한 계정·proof는 재사용한다.
5. 기본 요청 3회가 설명과 도구 왕복에 부족했다. 새 추천 연결은 지원 상한인 5회로 설정한다. 필수 관찰을 수집했다면 공유 예산의 마지막 요청을 최종 설명에 쓰고 불필요한 추가 도구 요청을 막는다. 필요한 관찰이 없으면 완료로 승격하지 않는다. 비교 전체의 공유 한도를 우회하지 않는다.
6. 추가 분석의 실행 근거에 Docker inspect/create 진단 덤프가 섞여 문맥을 소진했다. 실행 입력·출력·종료·제한·해시·실패 상태는 원문 값을 유지하고, 생략 필드를 표시한 근거 투영을 도구에 제공한다. 전체 근거는 로컬 원본 기록에 남긴다. 문맥 상한이나 검증을 느슨하게 하지 않았다.
7. 재개된 고급 연결의 표시가 계속 ‘확인 전’이었다. 결합된 실제 검사 결과로 표시하고 편집하면 다시 확인이 필요하다고 바꾼다. GPT와 로컬 AI 자원 설정 설명도 구분한다.

최초 사용자 오류의 원문·인증 자료가 없으므로 모든 최초 실패가 위 한 가지 원인 때문이라고 단정하지 않는다. 이번 실제 계정 작업에서 재현한 호환 결함과 진행·저장 결함을 증거로 수정했다.

## 기본값과 코드 검토

기본 추천 GPT-6.1 Sol. 분석 runtime/static/code 범위 활성화, 문맥 32768, 출력 요청 4096, 최대 요청 5, 대기 300초. 기능상 가능한 추가 분석은 보호된 도구 왕복 검사 후 선택하고, 사용자의 후속 수동 모드 선택은 유지한다. ChatGPT plan 출력 요청은 서버 강제 상한이 아니다.

GUI와 고급 ChatGPT 로그인은 한 흐름을 공유한다. UI 작업 슬롯·QThread 정리·다음 작업 예약·취소를 검사했다. 오류 메시지는 알려진 한국어 복구 안내를 사용하고 원시 인증 오류를 화면에 내보내지 않는다. 도구 설정 적용은 기존 설정 백업과 최신값 확인을 유지한다.

Black 26.10.1은 별도 도구 환경에만 설치했다. Python 109개 파일 구문 검사, 일관된 포맷과 변경 전후 AST 동등성을 확인했다. 새 실행 의존성은 없다. 단순 코드 포맷을 성능 향상으로 주장하지 않는다. 실제 불필요한 작업은 유효한 기능 검사 재사용과 과도한 진단 데이터 전송 감소로 줄였다.

## 이번 버전의 검증

- 최종 전체 자동 검사 903개: 실패·오류·건너뜀 0.
- 실제 ChatGPT 사용자 로그인, 모델 목록, 응답·JSON·도구 호출·왕복 확인. 토큰은 앱 보안 저장소에만 보관.
- 실제 계정으로 원클릭 연결부터 자동 도구 준비·비교 화면 진입 확인. 새 ProfileManager로 재조회해 도구 설정 후 보호된 proof 유지 확인.
- 소스와 최종 Windows EXE 각각 GPT-6.1 Sol 추가 분석 비교 완료. 할인 예제 6개 중 5개 일치, boundary-100 한 건 불일치. AI 해석의 스키마·ID·근거 인용을 재검증하고 보고서 링크·입출력·원본 사본 해시를 확인.
- 새 사용자 데이터에서 최종 EXE 시작/AI 설정 화면·종료, 키 마스킹·5개 제공자 설정·CLI 빈 이력 확인. 포터블 폴더에 실행 중 기록을 쓰지 않는지 확인.

## 근거와 제한

검증 자료는 `verification/gpt-ux-upgrade-20261115/evidence`에 보존했다. 실패한 시도도 보존하며 최종 성공과 혼동하지 않는다. 최종 빌드는 `build-attempt-3`, 실제 EXE 비교는 `native-real-gpt`, 원클릭/화면 검사는 `beginner-experience-5`, 소스 실제 비교는 `real-gpt-comparison-6`다. 개인 계정 자료가 있는 QA 전체를 배포하지 않는다.

다른 제공자 실제 키·계정 추론은 미검증이다. 새 PC에서는 Ghidra/Java·Docker 설치가 필요하다. 실측 대상은 Linux x86-64 ELF 콘솔 예제이며 임의 Windows GUI 대상이나 모든 입력의 동등성을 확인한 것은 아니다. AI 설명은 실측과 구분해야 한다. 호출 금액은 측정하지 않았다. 폴더 비교와 Rebuild는 보류한다.
